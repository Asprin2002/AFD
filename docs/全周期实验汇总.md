## 1. 可信静态网格(attention 专属)

**目的**：在不搬算子的前提下，验证"把未来-KV 的写入端在 GPU/PIM 间如何选/何时切"的收益区间。

**基本信息**：GPT-175B / 8×A100 / DIMM-PIM；grid = batch {1,2,4,8,16,32} × input {128,2048,5200,8192} × output {256,1024,4096,8192}，共 96 形状，95 个容量可行；对照 = 全 PIM KV 的 attention 基线；策略 = bounded-offline KV window / 64-token 重规划。

**结果**：

| B / 输入 / 输出 | 策略 | 加速比 |
| --- | --- | ---: |
| 16 / 5200 / 8192 | bounded offline KV window | **1.5074x** |
| 32 / 2048 / 4096 | bounded offline KV window | **1.4847x** |
| 32 / 2048 / 8192 | bounded offline KV window | **1.4001x** |
| 16 / 5200 / 4096 | 64-token replanning | **1.3742x** |
| 8 / 8192 / 8192 | bounded offline KV window | **1.2694x** |

其余统计：>1.01x 有 35 格，>1.10x 有 18 格，>1.20x 有 11 格；batch 2 与 4 无正 case；batch 1 最佳 1.0739x；B4/5200/4096 为 **0.9808x**（GPU attention 在 PIM 压力不足时反而变慢）。

**结论**：
- 收益集中在**大 batch + 长上下文 + 长输出**。
- batch≤4 无正收益，蕴含"压力不足则搬不动"的下界。
- 有一个 0.98x 的负例（B4）——策略并非单调正确。

## 2. 静态稠密算子布局（F-family，恒定放置）

**目的**：验证**恒定**地把 QKV / O 投影 / FFN 某一部分放到 PIM 执行的效果，与 1 相对。

**基本信息**：同一模型；候选 = DensePlan(o_proj, ffn, qkv) 梯子 + QKV/PIM 组合；记录 warm（权重已驻 PIM）与 cold（权重需拷贝入场）两档。

**结果**：

| B / 输入 / 输出 | 候选 | warm / cold |
| --- | --- | ---: |
| 2 / 128 / 256 | PIM QKV + 全量 O 投影 | 1.4295x / 1.2949x |
| 2 / 128 / 4096 | PIM QKV + 50% O 投影 | 1.4012x / 1.3935x |
| 2 / 128 / 256 | 全量 O 投影 + 12.5% FFN | 1.1963x / 1.1465x |
| 4 / 128 / 1024 | 全量 O 投影 + 12.5% FFN | 1.1923x / 1.1795x |
| 4 / 128 / 1024 | PIM QKV only | **0.9319x（输）** |
| 1 / 128 / 256 | 全部算子候选 | 0.74–0.99x（全输） |

**结论**：
- **增益来自 QKV 与 O 投影，不是 FFN**；加 FFN 反而从 1.43x 降到 ~1.20x。
- 算子迁移收益窗口**窄**：batch=1 全输、batch=4 开始分化、batch=2 为甜区。
- PIM FFN/GELU/residual/norm 属"未标定能力"，不承诺。

## 3. 在线实验

### 3.1 BurstGPT 32 请求 pilot

**目的**：在线语义下对比"因果联合调度"与"仅算子(F-only)"。

**基本信息**：BurstGPT trace，32 请求，PIM/G-P-G-P 模型。

**结果**：联合调度 ≈ F-only 或略差（多余的未来-KV 迁移给 GPU attention 增加 GPU 侧负担）。

**结论**：在线 32 请求下联合无明显优势；为负/中性 pilot。

### 3.2 Qwen-Coder 512 请求（满载）

**目的**：大请求、过载到达下，联合调度的端到端收益。

**基本信息**：512 连续请求，FCFS，max batch 64，decode-ready 到达；对照 = CHIME 风格独立基线（同 pairing）；联合 = LPT 子批量 + GPU 期望的 KV。

**结果**：

| 指标 | CHIME 基线 | 联合 | 变化 |
| --- | ---: | ---: | ---: |
| 模拟总时长 | 3796.54 s | 3457.61 s | **1.098x** |
| 吞吐 | 106.42 tok/s | 116.85 tok/s | **+9.8%** |
| 平均 E2E | 1520.30 s | 1457.14 s | −4.15% |
| P95 E2E | 3112.20 s | 2851.15 s | −8.39% |
| 平均 TPOT | 524.35 ms | 513.10 ms | −2.15% |

过程量：451 次 KV-writer 切换，9 次算子切换，PIM 驻留 ≈324 GiB dense 权重，瓶颈阶段明显移向 GPU。

**结论**：
- **1.10x 端到端 / +9.8% 吞吐**成立，但该 trace 严重过载（90s 到 512 请求、排空 ~3500s），属"容量/排空压力测试"，非稳态服务指标。
- 与 CHIME 相比同时叠加了 placement 与子批形成(LPT)两种效应，无法单独归因。

## 4. 异质联合静态矩阵（本轮，M0–M4）

**目的**：在**静态闭批**上一次性回答 M1-B/M2/M3：切段式"未来-KV 写入端 + 算子时间线"能否胜过(1)全 DC 菜单上的最优冻结计划、(2)独立规划器搜出的静态 best-static；编排轴(lpt/alignment)与成本轴(real/free)是否改变结论。

**基本信息**：
- 引擎：事件级 DenseOffloadCost + 合法性(XOR) + running-peak 容量。
- 六策略：control / attn(只迁 KV) / f_only(只迁算子) / joint(两相) / ffn_pilot / qkv_pilot。
- 对比：best_constant_menu(全 DC 合法冻结最优) + joint_static_reference(独立 best-static) + fresh-engine 重放校验。
- 成本臂：real(100us/切换 + 权重增量过 60GB/s) / free(全零)。
- 本轮重跑格：16/5200/8192、32/2048/1024、32/2048/4096、32/2048/8192、32/5200/4096（pilot 先导有 20 个 violation，其中 16 个不可行，经 `_kv_closure` 可行性修复后重跑）。

**结果**（速度比 = control_total / 该行 total_us；每个场景取 lpt/alignment 更优，两轴在本轮数值相等）：

| 场景 (B/输入/输出) | control | joint(=attn) | 加速比 | 独立 best-static | 相对 best-static | 切换数 kv/op | 成本轴 free==real |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 16 / 5200 / 8192 | 1793.9s | 1193.4s | **1.503x** | 1550.7s | +1.30x | 16 / 0 | 相同 |
| 32 / 2048 / 4096 | 802.4s | 566.4s | **1.417x** | 741.8s | +1.31x | 56 / 0 | 相同 |
| 32 / 2048 / 8192 | 2383.9s | 1773.0s | **1.345x** | 2140.9s | +1.21x | 16 / 0 | 相同 |
| 32 / 5200 / 4096 | 1402.0s | 1097.7s | **1.277x** | 1341.3s | +1.22x | 32 / 0 | 相同 |
| 32 / 2048 / 1024 | 127.7s | 112.9s | **1.131x** | 124.1s | +1.10x | 18 / 0 | 相同 |

辅助观测：
- attn == joint 逐格相同；f_only、ffn_pilot、qkv_pilot == control（算子维度本轮零贡献）。
  注意"本轮"= 5 个同质锚点重跑格"；异质格的 pilot 数字见 §6 更正——其中算子维度并非零贡献。
- best_constant_menu == control 逐格相同 → 全 DC 菜单上没有任何冻结计划优于朴素 control。
- 无不可行格、无 violation、fresh-engine 重放一致。
- 已知反例：pilot 曾记录 **B8/8192/8192** 的 joint(1133.6s) 输给其 best_static(958.3s)，+18%（保留在记录中，未在本轮重跑格内）。

**结论**：
- **方法在 5 个重点格全部成立**：1.13–1.50x，且稳定胜冻结与独立静态(×1.10–1.31)。
- 收益来源单一：全部来自"未来-KV 写哪"，算子侧零贡献（与第 2 节的 batch 依赖一致）。
- 成本模型不影响最优时机（free==real 逐格相同；real 总切换代价 ≤ 5.6ms 对 80 万 ms）。
- 组织成规律的收益条件：**效率 = (注意力压力) × (GPU 容量允许卸载比例) × (1 − PIM 固定载荷占比)**；大 batch、长输出、适量输入为甜区，容量与长输入是刹车。
- 编排轴在本轮完全退化（同质负载下 lpt==alignment），其真正差异要在异质负载下才显现（未跑）。

## 5. 跨实验一致性速览

- 可信网格与本次矩阵的 **16/5200/8192**：1.5074x(bounded window) vs 1.503x(joint 切段)，两个独立路径收敛。
- 算子迁移的 batch 依赖是**一致的**：早期 B1 全输 / B2 win / 本轮 B16-32 不输不亏（=control），未见矛盾。
- 在线 512 与本次矩阵都指向：**KV 写入端是主自由度和主要收益来源，算子侧始终付不划算的重量级**。
