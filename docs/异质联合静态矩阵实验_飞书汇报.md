# 异构静态矩阵实验汇报：切段式 KV 归属能否战胜一切“冻结”配方？

> 日期：2026-09-24
> 数据来源：`results/heterogeneous-joint-matrix-recheck/`（已观测运行输出，非机制预测）
> CSV 全量数据 / `summary.json` / `HETEROGENEOUS_JOINT_SUMMARY.md` 与本文同目录可查

---

## 一、一句话结论

在 GPU + DIMM-PIM 异构解码流水线上，**允许请求在其生成生命周期中途切换“未来 KV 缓存写在哪一侧”，能稳定战胜两类最聪明的“不动”方案**：① 全 DC 合法菜单里的最优冻结计划；② 一个独立规划器搜出的“终身只选一次写入端”的 best-static 方案。

本轮重跑的 5 个重点场景全部可行、全部获胜，加速比 1.13x–1.50x；收益来源非常单一且可归因——**全部来自“未来 KV 缓存的写入位置随时间迁移”，与算子侧（把算子搬到 PIM 执行）无关**。

---

## 二、系统模型（先把名词说清楚）

- **解码（decode）流水线**：请求在生成阶段逐 token 产出输出。每个已产出的 token 会留下它的键值缓存（**KV cache**，key/value 缓存，供后续 token 的注意力（attention）读取）。
- **KV 缓存放哪**：GPU 高带宽内存（**HBM**，本实验为 8×A100，合计 640 GiB、16.3 TB/s）或 **DIMM-PIM**（内存条内建处理单元，本实验 2048 GiB、13 TB/s，共享 60 GB/s 半双工 GPU/PIM 链路）。
- **提示 KV（prompt KV）**：输入阶段就产生的 KV，一开始就在 PIM 上，**永远不迁移**。
- **未来 KV（future KV）**：解码过程中即将产生的 KV。它的写入端（GPU 还是 PIM）可以在请求生命周期中途切换，这是本实验唯一的决策自由度。
- **算子（operator）**：QKV 投影、O 投影、FFN 等计算步骤，也可以合法地放在 GPU 或 PIM 执行（放 PIM 是一种“已验证但未标定”的能力，见第十节）。
- **“长阶段 / 短阶段”**：本工作沿用此前结论——解码中 **PIM 侧的注意力（attention，读取累计越积越多的 KV）是最长的一段**，是瓶颈；GPU 侧对应注意力的版本是“短阶段”。谁的 KV 少，谁的注意力就短。
- **分段（segmentation）计划**：把输出 token 时间轴切成若干段，每段采用不同的“KV 写入端 + 算子分布 + 子批编排”。本实验考察的核心对象就是这样的分段计划，对比对象是“整段不切、整个生命周期用一套固定方案”。

模型规模：GPT-175B，96 层，FP16，张量并行 TP=8；GPU 侧可用 KV 容量约为 314 GiB（640 GiB 扣除 326 GiB 权重与预留后的值，是本实验容量约束的关键数字）。

## 三、实验设计

### 3.1 矩阵的三个轴

| 轴 | 取值 | 含义 |
| --- | --- | --- |
| 场景（scenario） | 本轮重跑 5 个重点场景 | 固定 batch × 输入长度 × 输出长度 的整批离线负载 |
| 策略（strategy） | 6 种 + 2 条对比基线 | 搜索哪个决策自由度、搜索多深 |
| 成本模型（cost arm） | real / free | 段切换到底要不要算代价 |

另有两个固定维度：子批编排 **lpt**（长请求优先）与 **alignment**（成对预测分组），作为编排轴（见第八节）。

### 3.2 六种策略（每种给正式定义）

| 策略 | 搜什么 | 含义 |
| --- | --- | --- |
| control | 不搜索 | 对照：KV 全放 PIM、算子全放 GPU，永远不切。就是“最朴素的固定配方” |
| attn | 只搜未来-KV 写入端 | 算子固定全 GPU，只决定每段未来 KV 放哪 |
| f_only | 只搜算子时间线 | KV 固定全 PIM，只决定哪些算子、何时搬到 PIM |
| joint | 两阶段都搜 | 先算子时间线、后 KV 写入端 —— **主角** |
| ffn_pilot | 算子限子空间搜 | 只允许把 FFN 搬到 PIM（归因用：增益是否来自 FFN） |
| qkv_pilot | 算子限子空间搜 | 只允许把 QKV 搬到 PIM（归因用：增益是否来自 QKV） |

另两条**对比基线**（不参与搜索，是评估分段计划“价值是否为正”的参照）：
- **最优冻结计划**：在全部合法“恒定算子 + 恒定 KV”组合里挑最好的一个，全程不动不切。它代表“聪明但不分段”的上限。
- **独立 best-static**：一个**独立规划器**（JointAF，目标模型相关但规划算法独立）在同一事件引擎上，为每个请求选一次“终身只用一个 KV 写入端”的静态分配，再以真实成本重新评分。它代表“另一个团队、但同样只允许不动”的上限。
- **重放一致性校验**：把分段计划的最佳结果放到一个全新的同配置引擎上重算一遍，要求总耗时逐位相等——防止被已缓存计算污染比较。

### 3.3 成本模型双臂

- **real（真实成本）**：每次切换执行代价 100 微秒；若发生算子搬移，权重增量经 60 GB/s 链路拷贝。
- **free（零成本）**：所有切换代价归零。同一张分段计划分别在两臂下打分；搜索时机时用哪个臂是可以拆开的（搜索臂 × 报告臂）。
- 意义：**free 与 real 的差别 = “切换成本本身会不会改变最佳时机”**。

对比基线的评分方式：独立 best-static 因分配空间随 batch 指数增长，指定了评估预算（24 次全生命周期评估）；大 batch 场景会触顶，标为 `partial`（预算内最优，非全枚举）。本轮 5 个场景全部为 `partial`，文中凡说“独立 best-static”都是指“预算内最优的独立 best-static”，结论按此口径表述。

3. 5 个场景里 **4 个把 control 拉开 27% 以上**；唯一的低加速比场景（32/2048/1024，输出仅 1024）也在 13%，且仍是正收益。

## 五、效果分析一：哪些策略有效、为什么

### 5.1 attn = joint：算子维度在这批负载里是“无操作”

joint 先搜算子时间线、再搜 KV；而最终报告里 joint 与 attn 的耗时、切换次数**逐位相同**，算子切换恒为 0。含义：**operator 时间线这张牌在这批负载里没有任何值得打的空间**，joint 自动退化为 attn。

### 5.2 f_only = control、ffn_pilot = qkv_pilot = control：为什么搬算子到 PIM 永远不划算

把任何算子搬去 PIM 都需要把对应层权重经 60 GB/s 链路拷到 PIM、在 PIM 上跑、并让对应层的注意力/新 KV 仍留在 PIM（合法性的“互斥”规则）。结果：

- **任意算子维度都没有收益**——PIM 算子执行的吞吐在这个成本模型下并不比 GPU 快，却要付权重拷贝与更慢的执行；注意力瓶颈在“读 KV 的带宽”、不在“算算子”，所以搬算子减不了长阶段。

更关键的是**互斥**：想用 PIM-QKV，就必须让未来 KV 留在 PIM → 等于主动放弃唯一挣钱的自由（KV 迁移）。所以 qkv_pilot 的“最优”就是根本不搬 = control；ffn_pilot 亦同。这一步把功劳范围划得很干净：

> **增益全部来自 KV 写入端的时间迁移，占贡献 100%；算子侧贡献为 0。**

### 5.3 最优冻结计划 = control：只有“会动的”才能赢“固定的”

即使把全部合法恒定组合放开挑最优，最优冻结计划也正好等于 control（全 GPU 算子 + 全 PIM KV）——说明**任何“不动”的配方都不可能比朴素配方更好**；唯一能赢得它的就是分段切换本身。对照因此不空转：分段方案的胜局坐实了“动比不动强”。

### 5.4 分段 vs 独立 best-static：赢在“允许中途换”

独立 best-static 允许每个请求终身选一次写入端（比如 16 个请求里挑 8 个放 GPU、8 个留 PIM），但它**不允许中途换**。分段方案在它上面再赢 **10%–31%**：最佳时机是把一批请求在生命周期中部（约半程）集体切去 GPU，让后半程最沉重的注意力读取用上 GPU 的短阶段，从而摊薄切换成本。

**为什么 mid-life 迁移划算**：注意力每 token 要读“自己此前所有 token 的 KV”，越到后面读得越多；把未来 KV 切去 GPU 就等效于后半程每分钟都在用“快的那条路”。迁移发生在 KV 读量还小时（代价小）、收益发生在读量大时（收益大）——这是“迟早迁移”与“一生迁移”的分水岭。

## 六、效果分析二：哪些场景有效、为什么

加速比排序：**16/5200/8192（1.503x）> 32/2048/4096（1.417x）> 32/2048/8192（1.345x）> 32/5200/4096（1.277x）> 32/2048/1024（1.131x）**。

三个决定收益大小的因素，逐一解释：

**因素 1：可卸载的注意力压力（增量收益的来源）** ∝ batch × 累计 KV 读取量（每 token 读全部前缀 KV，量级 ≈ batch × 输出长度²）。batch 越大、输出越长，后半程“用 GPU 短阶段”的份量越重，收益越放不下。这也解释了“小 batch（2/4）在这张表上无正收益”——注意力压力太低，连切换成本都摊不回来。

**因素 2：GPU 可用 KV 容量上限（≈314 GiB）**。未来-KV 一旦写 GPU 就只增不减，总未来 KV = batch × 输出 × 每 token KV。超过 314 GiB 的部分必须留在 PIM 或中途切回，是硬约束。这解释了两个数字：
- **32/2048/8192** 输出极长，理论压力最大，但总未来 KV（32×8192×每 token KV ≈ 1152 GiB）远超 GPU 容量，能搬的只有一部分（本例仅 16 个请求被切去 GPU，其余留在 PIM）→ 加速比被容量卡在 **1.345x**，未及 1.417x。
- **16/5200/8192** 只有 16 个请求，且全部 16 个都切换、无中途切回；要可行，切换时刻只能发生在后半程（算术约束：16 个全切且不超容 ⇒ 切换起点须 ≥ 全部输出约 45% 之后）→ 后半程最重的注意力读取恰好享受 GPU 短阶段 → 拿到全场最高 **1.503x**。

**因素 3：卸不掉的固定载荷（PIM 上的提示 KV）**。输入越长，提示 KV 越早越多、且永远留在 PIM——这部分注意力永远走长阶段，压缩了可优化空间。**32/5200/4096（1.277x）< 32/2048/4096（1.417x）**：两者 batch、输出都相同，唯一差别是输入更长 → 固定载荷更大 → 收益更低。这是三个因素里最干净的“配对实验”。

**短输出平庸的原因（32/2048/1024，1.131x）**：输出仅 1024，前缀积累少，且一生只有 1024×batch 的 KV 要读，迁移摊不薄成本。临界点附近的弱收益区。

> 一句话规律：**收益 =（batch × 输出带来的注意力压力）×（GPU 容量允许卸载的比例）×（1 − PIM 固定载荷占比）**。大 batch、长输出、适量输入，是收益甜区；容量与固定载荷是两支刹车。这也与既有可信网格“收益集中在大 batch / 长上下文 / 长输出”的历史结论同向。

## 七、成本模型的影响（free vs real）

- free（切换代价全零）臂搜出的最优时机，在 **全部 5 个场景**上与 real 臂逐位相同（耗时、切换次数全一致）。
- 这不是“搜索代码根本没读价格”的空相等：搜索的接收判据确实把切换代价（100us × 请求数）计入相对改善阈值。更合理的解释可从**已观测的总额**读出：即使取最坏口径，把全部切换代价（56 次 × 100us ≈ 5.6ms）对照整段耗时（约 80 万 ms）只是 0.001% 量级；收益幅度达数十万毫秒，足以让“要不要迁”的阈值判定两侧结果一致，于是两臂踩在同一时机上。
- 结论应有的色彩：这是**大收益区**的稳健性声明（切换成本再翻十百倍也不改时机），**不适用于**收益薄的边缘场景（例如第八节的反例），在那里切换成本可能恰好压垮决策。

## 八、编排轴（lpt / alignment）的观察

本轮 5 个场景全部为**同质锚点**负载（所有请求同构：同样的输入、输出长度）。这类负载下，无论按长请求优先还是预测配组，子批内部都是同一批请求，编排改不动结果——两轴数值逐场景完全一致，属预期退化。

编排轴真正的试金石是**异质负载**（长输入 / 长输出 / 混合各 profile），它们在本轮重跑范围之外；本报告不改写编排轴的结论，只如实记录“同质锚点上编排无关”。

## 九、局限性与诚实边界（避免过度解读）

1. **搜索是有界确定性搜索，不是无穷无界规划器**。分段最多 3 段；≥4 段的更复杂方案“没被发现”不等于“不存在”。数字是“在搜索预算内找到的最优”，结论口径如此。
2. **独立 best-static 在预算内而不是全枚举**（24 次评估，大 batch 触顶标 `partial`）。分段仍以 10%–31% 裕度赢它；若全枚举真值更低，分段赢面只会略收窄，不会翻转。
3. **已保留的真实反例**：此前运行中 **8/8192/8192** 的分段 joint（1133.6s）输给它自己的独立 best-static（958.3s，约 +18%）——小 batch + 极限长输出的薄收益区，一次性固定分配反而更好。它被如实地记录为“分段并非总是最优”的负样本，是本工作诚实性的一部分，而非偶发噪声。
4. PIM 算子（FFN/QKV/O 投影）执行在本工作成本模型里被建模为**已验证但未标定的能力**；本实验证明它们在当前参数的“联合分段”框架里无增益，但不能据此断言真实硬件上的 PIM 算子执行一定无用（需要单独标定敏感性）。
5. 负载为“整批变长离线闭批”，测的是**负载突变切换**能力，不是在线到达率语义；在线/到达率是另一个独立的实验范畴。
6. 若干成本默认（运行预留、DMA 固定延迟、分配碎片开销）为乐观取值，需后续敏感性分析。

## 十、结论与建议

1. **核心结论**：允许未来-KV 写入端随时间迁移，在同一事件级模型上稳定击败最优冻结计划（≈control）与独立静态分配（+10%~31%），在重点网格达 1.13x–1.50x。
2. **收益归因极其单一**：100% 来自 KV 写入端迁移；算子侧（PIM-FFN / PIM-QKV）在本框架内为零贡献。后续若要继续挖增益，应聚焦“更大的 KV 迁移自由度”与“容量/固定载荷这两支刹车”。
3. **甜区规律**（batch × 输出 × 容量约束 × 固定载荷）可作为后续负载选择的指导：大 batch 长输出是主攻方向，短输出、小 batch、超长输入应视为低收益区。
4. **工程修复已验证**：为“贪婪短窗口会漏看长尾容量悬崖”加装的全生命周期可行性修复，把 1.5x 级结果从不可行救回且与可信网格重合；该修复与其回归测试一并保留在流水线内。
5. **下一步建议**：
   - 对异质负载跑编排轴（lpt/alignment 真正的试金石）；
   - 对 8/8192/8192 这类反例做敏感性分析，刻画“分段失利的边界在何处”；
   - 对成本默认值（切换代价、链路带宽、权重拷贝策略）做敏感性扫描，量化第七节结论的稳健区间。

| 术语 | 含义 |
| --- | --- |
| KV cache | 解码中每个已产出 token 留下的键值缓存，供后续注意力读取 |
| 提示 KV / 未来 KV | 输入阶段已存在（PIM 上，永不迁） / 解码中将产生（写入端可切）的 KV |
| DIMM-PIM | 内存条内建处理单元；本实验 2048 GiB、13 TB/s |
| GPU HBM | 8×A100 高带宽内存；640 GiB、16.3 TB/s；可用 KV 约 314 GiB |
| 长阶段 / 短阶段 | PIM 侧注意力（最长，瓶颈） / GPU 侧对应阶段 |
| 分段计划 | 输出时间轴分段，每段一套 KV 写入端 + 算子分布 |
| 最优冻结计划 | 全合法恒定组合里的最优者，全程不动（本实验值恰 = control） |
| 独立 best-static | 独立规划器搜出的“每次请求一生只选一次写入端”静态方案（预算内最优，标 partial） |
| control / attn / f_only / joint / ffn_pilot / qkv_pilot | 见第三节表 3.2 |
| real / free 成本臂 | 切换代价 100us+权重拷贝 / 全零；两臂之差 = 成本对时机的影响 |
| 重放一致性校验 | 结果在新引擎上重算必须完全相等，防止缓存污染 |
